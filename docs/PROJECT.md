# 范围与技术决定

## 产品范围

MoleMonitor 提供常驻菜单栏的只读状态查看。监控与清理分别执行：监控应用不暴露清理操作；需要清理时，可通过独立的 Mole CLI 或其他明确授权的流程处理。

| 位置 | 当前实现 |
|---|---|
| 菜单栏 | CPU、内存占用百分比、上下行网络速率 |
| 展开面板 | CPU/内存概览、已用与总内存、内存压力、磁盘剩余空间 |
| 电池与散热 | 电量、充电/外接电源状态、循环次数、CPU 温度、电池温度、风扇 RPM |
| 应用与进程 | 按应用归并进程，CPU/内存两种排行，各显示前五名 |
| 控制 | 展开、关闭、切换排行、退出 |

每应用耗电排行不在当前范围内，CPU 使用率不能替代能耗测量。也不提供清理、自动删除、sudo、特权 helper、SMC 写入或风扇控制。

界面已实现并检查过静态预览；真实菜单栏操作尚未验收，详见 [VERIFICATION.md](VERIFICATION.md)。

## 架构与技术决定

应用采用 AppKit 的 `NSStatusItem` 和 `NSPopover`，内部使用 SwiftUI 展示。基础 CPU、内存、网络和磁盘指标复用固定版本的 Mole 状态采集器；电池、内存压力、温度和风扇通过只读系统接口补充。

| 模块 | 职责 |
|---|---|
| `Sources/MoleMonitor.swift` | 菜单栏与面板、NDJSON 解码、应用排行、数据有效性及子进程生命周期 |
| `Sources/Sensors.swift` | 只读 AppleSmartBattery、内存压力 sysctl 与 AppleSMC 读取 |
| `scripts/fetch_status.py` | 固定官方版本下载、缓存验证和 SHA-256 核验 |
| `scripts/build.py` | 下载并核验固定采集器、编译 Swift、组装 App 与本地签名 |

采集器固定为 Mole 官方 `V1.59.1` 的 arm64 发布文件，来源与 SHA-256 见 [NOTICE](../Vendor/NOTICE.md)。构建时下载到忽略的本地缓存，公开仓库不分发其二进制。运行使用 `--watch --interval 2s --proc-cpu-alerts=false` 持续获取 NDJSON，后台分行解码。该参数关闭进程告警，不会取消上游进程采集；上游采集范围比界面展示内容广，常驻总成本需实测。

应用通过环境变量关闭上游 Finder AppleScript 查询，采用其现有磁盘查询回退，避免自动化授权弹窗。传感器实现参考 SMCKit/Stats 的协议和键目录，保留第三方 MIT 归属；未知芯片、缺失传感器与读取失败均显示不可用。

应用排行另用 `ps` 的 CPU/RSS 和可执行名称归并，不读取完整命令参数。采集、解码和排行在后台；界面在主线程。每次只维持一个状态采集子进程，超过时限没有有效数据时终止并重试；子进程失响应时可升级终止。退出时关闭该子进程，唤醒时清空旧状态并等待新样本。

## 数据口径

- CPU 温度是按芯片家族选择的可读 CPU 传感器均值，不是最热核心或所有温度点的均值。
- 应用 CPU 使用单核 100% 的口径；归并多进程后可超过 100%。
- 应用内存为 RSS 合计，共享页可能重复计入，与活动监视器显示值不同。
- 网络使用上游选定路由/隧道的聚合历史，不把全部接口相加，避免 VPN 与物理网卡双算。
- 内存压力按系统标志解释为正常/警告/严重，不由内存百分比自行推导。
- 缺失、过期、失败或占位零值保留未取得/采集中状态；成功测到的风扇 0 RPM 与未知分别处理。

## 当前限制与后续条件

第一版的构建目标为 Apple Silicon、macOS 14+；目前只在一台 Apple M5/macOS 27 设备上短时验证，其他芯片和系统版本未实测。构建产物使用本地 ad-hoc 签名，尚未公证或提供 GitHub Release 成品，构建不会安装应用或设置登录启动。

长期功耗、睡眠/唤醒、网络切换和真实 GUI 开销仍待验证。若上游采集器常驻成本过高，或固定协议不再满足需要，可评估用原生 API 采集少量指标。数据异常或高占用不会触发自动删除与清理。
