# 验证摘要与待验项

## 已完成的检查

2026-10-10，在一台 Apple M5/macOS 27 设备上完成以下检查。原始诊断含本地目录与应用快照信息，未随公开源码分发；本页保留结果、方法和覆盖边界，不宣称完整验收。

| 检查 | 结果 | 覆盖边界 |
|---|---|---|
| 90 秒真实采样 | 取得 44 帧，CPU、内存、网络、电池、传感器和应用数据有值 | 无界面运行，没有创建菜单栏 UI |
| 同次资源采样 | 45 次 App 与后代进程采样：CPU 均值约 0.49%、峰值 4.9%，峰值 RSS 37.9 MiB；退出后已知关联进程残留为 0 | 不包含可见 GUI，不能外推长期耗电 |
| 受控故障恢复 | 坏 JSON 行、分片数据、后端忽略 TERM 并停止输出时，监控能终止后端并恢复采集 | 故障注入不代表真实睡眠/唤醒 |
| 最终构建短诊断 | 22 秒取得 12 帧，退出码 0，stderr 为 0 字节 | 当次短时数据，不是长期稳定性承诺 |
| 静态预览 | 使用当次真实数据生成并检查了静态面板图 | 非 App 窗口截图，不证明菜单点击通过 |
| 构建与协议 | 构建、`--self-test`、本地签名验证及文档检查通过 | 不代替 GUI、兼容性或长期运行验收 |
| 目录整理后复核 | 重新构建、协议检查、签名与 ZIP 校验通过；22 秒取得 12 帧，退出码 0，stderr 为 0 字节 | 迁移复核不扩大原有功能覆盖范围 |
| 开源源码构建 | 从无采集器缓存的待提交源码副本下载固定官方资源，核验 SHA-256、构建、协议检查与签名验证通过；无效缓存拒绝检查通过 | 证明首次源码构建路径可用，未创建可见 UI |

`--self-test` 覆盖结构化解码、样本时间、缺失/失败占位值、网络聚合和坏 JSON。上述测试中的 CPU 与内存数据来自短时资源采样，不是能耗测量。

## 仍待验收

- 真实菜单栏展开/关闭、CPU/内存排行切换、退出、深浅色和屏幕空间适配。
- 实际睡眠/唤醒后的过期状态、采集重启与是否重复启动子进程。
- Wi-Fi、VPN、默认路由切换、断网与恢复。
- 长时间后台稳定性，以及完整可见 App 的 CPU/内存和电池影响。
- 其他芯片、无风扇/无电池设备与 macOS 14 的实际兼容性。
- 公证和跨设备分发；当前没有 GitHub Release 成品。

现有验证没有安装应用、设置登录项或执行清理。首次在新的机器上运行时，应分别确认传感器可用性和数值口径。

## 检查方法

从项目根目录执行：

```bash
python3 scripts/build.py
dist/MoleMonitor.app/Contents/MacOS/MoleMonitor --self-test
codesign --verify --deep --strict dist/MoleMonitor.app
dist/MoleMonitor.app/Contents/MacOS/MoleMonitor --diagnose --seconds 22
```

首次构建需要网络以下载并校验固定版本的状态采集器。诊断命令不创建状态栏或可见窗口；需要静态预览时，在参数后加 `--preview <绝对输出路径>`。

新增测试应记录日期、设备与系统、采样时长、退出/错误状态及覆盖范围。对外提交诊断材料前应去除本地路径和应用快照等无关信息。真实 UI 检查、无界面采样与静态预览须分别记录。
