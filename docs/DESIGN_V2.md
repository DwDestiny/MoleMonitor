# MoleMonitor 面板 v2 设计

本文档定义面板 v2 的完整设计：菜单栏图标、英雄区比熊动画、分项区、侧栏明细、异常区和一键复制提示词。本文档取代 [DESIGN.md](DESIGN.md) 中第 13 章列出的章节和门禁。没有被列出的旧章节继续有效。

- 状态：设计稿，待甲方验收。
- 日期：2026-10-12。
- 范围：Mac 应用 `Sources/App/`、核心逻辑 `Sources/Core/`、CLI `Sources/cli/`、CI 门禁 `scripts/ci_acceptance.py`。
- 产品边界：见 [PROJECT.md](PROJECT.md)。本文档不改变“只检测、只预警、只读”的边界。

## 0. 来源与术语

### 0.1 用户原话（设计依据）

本设计以下面的用户原话为依据。各章的决定都可以追溯到这些原话。

| 编号 | 原话 | 日期 |
|---|---|---|
| U1 | 做一个好看、方便、极其轻量的mac状态监测工具结合mole cli使用，代替当前电脑很重的cleanmymac | 首次需求 |
| U2 | 那既然我们的这个定位是监测加问题提醒，那就是问题优先原则！我们要突出的是状态和问题！没问题的就统统靠后 | 后续决定 |
| U3 | 所有的这些东西，都应该你来定，你按照获奖标准来出，我只是作为你的甲方来验收，明白吗 | 后续决定 |
| U4 | 我说的验收还包括交互、丝滑动效和优雅的现代化UI | 后续决定 |
| U5 | 面板可以搞得酷一些，动态图表那种 | 后续决定 |
| U6 | 当前这个设计还是有很大的问题，这个静态的小狗完全体现不出我想要的可爱、有趣的特色，现在这种状态栏太多了，你明白吗，我们要搞出一些有趣的点子出来，另外就是当前这个面板、信息的展示、悬停的交互、按钮的设置，全都非常的不产品，一点都不专业！我希望的是，首先要有一个状态位置，通过状态栏icon提现初步的状态；然后面板一进来，通过小狗的动作动画、消息气泡这种交互，告诉机主当前状态，然后是一个分项区域，展示各个分项的状态、数值、悬停后在侧面打开分享单独的明细或者app排行，这样交互不好吗？一个异常告警，有无异常或者异常记录等，再提供一个一键复制优化提示词的功能即可，这个文案也要考虑考虑，信息排版、文字排版、图表交互这些统统都要好好设计一下，可以接受一定程度的运行资源占用，合理范围即可，尽量优化 | 2026-10-12 |

其他已定事实：狗是比熊。CPU 用“速度”类比。目标是 Apple Design Award 的水准。

### 0.4 数值单位

- 尺寸单位是 pt。截图和位图单位是 px，@2x 时 1 pt = 2 px。
- 时长单位是 ms 或 s。
- 帧率单位是 fps。步频单位是 Hz（步每秒）。
- 气泡字数用“宽度单位”：一个全角字符（中文、全角标点）计 1，一个半角字符（字母、数字、半角空格、半角标点）计 0.5。

## 1. 目标与不做

### 1.1 目标

面板 v2 要让机主在 3 秒内知道三件事：电脑现在好不好，哪一项有问题，下一步做什么。

| 编号 | 目标 | 可测的标准 |
|---|---|---|
| G1 | 菜单栏图标给出初步状态 | 五态在 1x 菜单栏可以互相区分（第 9 章） |
| G2 | 比熊用动作和气泡说出当前状态 | 打开面板后 300 ms 内动作与状态一致，气泡 ≤24 宽度单位（第 4 章） |
| G3 | 问题优先（U2） | 问题分项置顶并染色，正常分项灰阶，全绿时只有一处绿色（第 5 章） |
| G4 | 明细在侧面打开（U6） | 悬停 350 ms 或点击打开侧栏，同一窗口，≤250 ms（第 6、10 章） |
| G5 | 异常可见，异常可追溯 | 无异常只占一行，异常记录保留 30 天（第 7 章） |
| G6 | 一键复制提示词 | 底部只有一个主按钮，复制后 100 ms 内有反馈（第 8 章） |
| G7 | 丝滑与轻量（U1、U4、U6） | 面板打开 60 秒进程 CPU ≤3%（真机），关闭后无高频定时器（第 11 章） |

### 1.2 不做

下表的项目不做。后续工作包也不得加入。

| 不做 | 理由 |
|---|---|
| 清理、删除、卸载、结束进程 | 产品只读。清理由用户的 Agent 调用 Mole CLI |
| sudo、特权 helper、SMC 写入、风扇控制 | 红线，见 [AGENTS.md](../AGENTS.md) |
| 每应用耗电排行 | 红线。macOS 没有可靠的公开每应用耗电读数 |
| 用 CPU 使用率估算耗电 | 红线。估算会误导用户 |
| 每 App 网络排行 | 没有公开接口。见 6.5 |
| 饭盆、骨头、背包、表情包等第二套隐喻 | 一个隐喻更好懂。见 4.1 |
| 设置窗口、偏好页 | 选项只有 3 个，放在“…”菜单 |
| 菜单栏图标持续动画 | 菜单栏动画会分散注意力，也会持续耗电 |
| 实时点落盘 | 2 秒实时点只在内存中，关闭面板即清空 |

### 1.3 从现状删除的元素（回应 U6“状态栏太多”）

| 删除的元素 | 现状位置 | 替代 |
|---|---|---|
| 正常项折叠行 | 问题卡下方 | 6 行分项全部显示，正常项灰阶 |
| 状态灯带 | 英雄区下方 | 分项行的状态点 |
| 每行复制图标 | 问题行右侧 | 底部唯一主按钮 |
| “更多”行与第二屏 | 面板底部 | 侧栏 |
| App 排行独立区块 | 面板中部 | 侧栏中按分项显示 |
| 底部多按钮（设置、退出、复制命令） | 页脚 | “…”菜单 |
| 三档面板高度 332/560/620 | 面板整体 | 按异常条数变化的高度公式，见 2.3 |

## 2. 信息架构与线框

### 2.1 信息顺序

面板从上到下按“状态 → 分项 → 异常 → 行动”排列。菜单栏图标在面板之前给出初步状态。

| 顺序 | 区域 | 回答的问题 | 首屏可见 |
|---|---|---|---|
| 0 | 菜单栏图标 | 有没有问题，多严重 | 是（面板关闭时） |
| 1 | 英雄区 | 现在怎么样（一句话） | 是 |
| 2 | 分项区 | 哪一项，数值多少，趋势如何 | 是 |
| 3 | 异常区 | 有几条异常，持续多久，过去有没有 | 是 |
| 4 | 底部 | 下一步做什么 | 是 |
| 5 | 侧栏 | 这一项的明细和 App 排行 | 按需打开 |

面板不滚动。侧栏内部可以滚动。

### 2.2 宽度与网格

主列宽 352 pt。现状宽 328 pt。主列加宽 24 pt。理由：分项行要同时放两行文字、88 pt 大数值和 84 pt 迷你曲线。在 328 pt 内，迷你曲线只剩 60 pt，读不出趋势。

| 参数 | 值 |
|---|---|
| 主列宽 | 352 pt |
| 左右内边距 | 16 pt |
| 内容宽 | 320 pt |
| 网格 | 4 pt。所有尺寸和间距是 4 的倍数，文字基线除外 |
| 侧栏宽 | 320 pt（含 1 pt 分隔线和 16 pt 内边距，内容 287 pt） |
| 侧栏展开后面板总宽 | 672 pt |
| 窗口圆角 | 12 pt |
| 静态预览宽 | 704 px（主列 @2x）、1344 px（展开侧栏 @2x） |

### 2.3 高度公式

| 区块 | 高度 |
|---|---|
| 顶部内边距 | 12 pt |
| 英雄区 | 152 pt |
| 英雄区到分项区 | 8 pt |
| 分项区 | 6 行 × 40 pt = 240 pt。台式机没有电池：5 行，200 pt |
| 分项区到异常区 | 12 pt |
| 异常区，无异常 | 36 pt |
| 异常区，有异常 | 标题 28 pt + 每条 44 pt，最多 3 条 |
| 异常区到底部 | 12 pt |
| 底部 | 40 pt |
| 底部内边距 | 12 pt |

| 异常条数 | 总高（笔记本） | 总高（台式机） |
|---|---|---|
| 0 | 524 pt | 484 pt |
| 1 | 560 pt | 520 pt |
| 2 | 604 pt | 564 pt |
| 3 条或更多 | 648 pt | 608 pt |

规则：

1. 面板高度只在异常条数变化时改变。
2. 刷新数值、悬停、打开侧栏都不改变高度。
3. 高度改变时，顶边固定，底边移动，动画 220 ms。RM 时直接改变，无动画。
4. 高度改变只在面板打开期间发生。面板在下一次打开时直接用新高度。

### 2.8 四种数据状态的区分

| 状态 | 状态点 | 数值 | 迷你曲线 | 说明行 |
|---|---|---|---|---|
| 测得 | 按等级 | 实际值，零值显示“0%”或“0 B/s” | 实线 | 正常说明 |
| 采集中 | 空心圆 | 有值显示值，无值显示“采集中” | 虚线占位 | “正在采集” |
| 过期 | 虚线圆 | 最后值，灰色，前面加时刻 | 灰色实线，末端截止 | “停在 13:20” |
| 缺失 | 横线“—” | “—” | 无 | 缺失原因，例如“这台 Mac 没有电池” |
| 失败 | 叹号圆 | “读取失败” | 无 | 失败原因，例如“SMC 不可用” |

测得的零值与缺失必须看起来不同：零值有数字，缺失是“—”。
